# Implementation and verification report

This report compares the requirements in `requirements.md` with the current implementation. “Not verified” means no execution evidence is recorded here; source-code inspection alone is not a passing test. Reproducible checks below are intended to be run against the local stack described in the project README (MongoDB, API on `127.0.0.1:3000`, and client on `127.0.0.1:5173`). No new tests were run while preparing this report.

## Traceability

| Requirement | Implementing module/component/endpoint | Reproducible test or demonstration | Verification outcome and limitation |
|---|---|---|---|
| FR-01 Account registration | `routes/auth.js` `POST /api/auth/register`; `client/src/LoginForm.jsx` | Submit a valid username/password in Create Account and inspect the response or log in. | The user can create an account and use the application after submitting a unique username and a password. |
| FR-02 Unique usernames | `models/PrimerUser.js` unique username index; `routes/auth.js` duplicate-key handling | Register the same normalized username twice; second request should return HTTP 409. | The second account with the same username will be rejected. |
| FR-03 User authentication | `routes/auth.js` `POST /api/auth/login`; `auth/token.js`; `middleware/requireAuth.js` | Log in with correct credentials, then try an incorrect password and a protected endpoint without a token. Expect token, HTTP 401, and HTTP 401 respectively. | If a user inputs an incorrect username and/or password, their login attempt will be rejected. |
| FR-04 Logout | `client/src/App.jsx` `endSession` and Log out button | Log in, click Log out, and confirm the signed-in view disappears; then try reusing the prior bearer token against `/api/chats`. | Slight limitation where a copied token could be used until it expires after 15 minutes. |
| FR-05 User identification | `routes/chats.js` message serialization; `client/src/ChatPanel.jsx` sender display | Send messages from two accounts and verify displayed sender names; inspect `GET /api/chats/:id/messages`. | The sender's username is found from their logged in account, and the username(s) to send the messages to is stored in each chat. |
| FR-06 Private chat creation | `routes/chats.js` `POST /api/chats`; `client/src/App.jsx` | As account A, create a chat with account B; verify it appears in A’s chat list and, in B’s list. | The chat is created and visible in the both member's chats. |
| FR-07 Private messaging | `routes/chats.js` `POST /:chatId/messages`; `client/src/ChatPanel.jsx` | With two accounts in a direct chat, send a message as A and check B’s view and message history. | Sent messages are visible in both chats. |
| FR-08 Message history | `models/Message.js`; `routes/chats.js` `GET /:chatId/messages` | Send a message, restart the API/client while retaining MongoDB data, then reopen the chat and verify the message remains. | MongoDB persistence and retrieval are implemented so message history is preserved. |
| FR-09 Group chat creation (three or more users) | `routes/chats.js` `POST /` and `POST /:chatId/participants` | A creates a direct chat with B, adds C, then verify all three see the same chat and can load its history. | A group can be formed by promoting a direct chat when a third participant is added. |
| FR-13 Group messaging | `routes/chats.js` message endpoints; `client/src/ChatPanel.jsx` | After forming a three-person group, send as one member and retrieve as another member. | The message history is shared throughout the group. |
| FR-14 Group message history | `models/Message.js`; `routes/chats.js` history endpoint | Send a group message, restart the client/API, and retrieve it from a member account. | MongoDB persistence and retrieval are implemented so message history is preserved. |
| FR-15 List conversations | `routes/chats.js` `GET /`; `client/src/ChatList.jsx` | Log in as a participant and compare the displayed list with chats that account belongs to; try another account. | Only the chats they are a member of are listed. |
| FR-16 View chat members | `routes/chats.js` `viewChat`; `client/src/ChatPanel.jsx` | Open a group chat and compare the Members line with the expected participants. | Members of a group chat are listed. |

| NFR-02 Authorization checks | `middleware/requireAuth.js`; `routes/chats.js` `memberChat`; `realtime/chatSockets.js` | Without auth, request REST resources and connect a socket; as a non-member, request history/send and emit `chat:join`.
